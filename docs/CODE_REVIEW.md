# Career Compass 代码与架构审查

日期：2026-11-03（America/New_York）；包含同日英文界面与工作流更新。
依据：`docs/PROJECT_BRIEF.md`。本次范围是现有 Next.js 原型的审查、界面和交互优化、本地验证；没有部署、建立远端仓库或连接真实账号。


## 本轮用户反馈落实

- UI 文案、状态、示例内容、提示与 HTML 语言均改为英文；用户自行填写的文本保持原样。
- 推荐排序使用 60% 中大型科技企业 / 20% 中国出海企业 / 20% 初创与小企业的加权轮转。来源不足时不编造岗位，不重复占位；筛选后的实际比例可不同。
- Overview 移除顶部发现按钮及右侧全部卡片。顺序为核心指标、Application progress、行动、机会列表、联系人列表；后两者均有跳转入口。Applied 指标统计已提交申请（包含测评、面试和最终结果），与进展栏的当前阶段计数区分。
- Applications 默认 Table，支持手动新增和单元格编辑；同一份 `Workspace.jobs` / `applications` 驱动 Table、Board、Overview、Opportunities。阶段新增 To apply，移除 Withdrawn，Saved 继续作为收藏列表。
- 岗位卡片展示截止时间、sponsorship、核心职责、关联点、待确认项和 JD 链接。没有来源的示例链接禁用；用户填写的 http(s) 原始 JD 可在岗位、表格和看板打开，不自动标记投递。
- 全局容器取消固定最大宽度，字号放大，岗位和联系人列数随屏幕变化；Overview 全宽展示。桌面 Outreach 队列与编辑器等高，窄屏纵向排列；移动导航使用短英文标签。
- 本地结构升级为 v2，保留原存储键并迁移 v1；已存个人介绍、联系人和外联草稿不会重置。旧 Withdrawn 转入 Saved，备注记录原状态。
- 新增 `app/components/application-form.tsx`、`app/lib/migration.ts`；更新全部功能组件、模型、示例、逻辑、存储、样式、测试和 PROJECT_BRIEF。

## 审查结论

原版本可以演示岗位列表和投递阶段，但尚未覆盖 brief 中“发现 → 联系 → 外联 → 投递”的完整界面。最大缺口不是缺少装饰，而是人脉和外联没有进入核心流程。继续在单一 `app/page.tsx` 中增加条件分支，会让业务状态、示例数据与展示逻辑耦合得更紧。

本次保留 Next.js / React / TypeScript 与现有依赖，使用 App Router 独立路由、共享导航、按功能拆分的客户端组件、独立领域模型和本地预览存储。阶段一可以继续迭代；真实自动化还需要完整服务端，不应把 localStorage 原型直接上线用于私人求职数据。

## 发现与处理

| 优先级 | 原问题 | 影响与本次处理 |
| --- | --- | --- |
| P1 | 人脉与外联只有占位按钮 | 缺少 brief 明确要求的 LinkedIn 流程；新增联系人、双渠道外联、可编辑模板、复制、主页跳转、人工状态和关注日期 |
| P1 | 所有页面由一个组件的 `view` 状态切换 | 页面无法直接链接、刷新丢失当前位置；改为六条 App Router 路由 |
| P1 | `regionFilter` 不参与筛选，岗位方向只有 Product 切换 | 控件表现与实际结果不一致；改为地区、PM/DS/DA、关键词的组合筛选 |
| P1 | `job.id + 100` 与初始投递 ID 不是统一身份 | 同一岗位可重复进入看板；投递改为稳定 `jobId` 关联，收藏保持已有阶段 |
| P1 | 示例无依据地显示支持 sponsorship、精确匹配分数 | 容易形成过度确定的判断；改为三项工作授权状态及依据，无证据默认未知，展示方向关联与待确认项 |
| P1 | TikTok 示例未遵守默认排除 | 新增可逆公司排除设置与“已排除”视图，保留原因 |
| P1 | 状态仅保存在内存 | 刷新后无法持续跟进；新增有版本校验、异常提示的浏览器本地存储及导出 / 重置 |
| P2 | 移动端隐藏整个侧栏、字号最低不足 8px | 导航不可用且阅读困难；手机保留六项底部导航，正文和输入框提升可读性 |
| P2 | 硬编码日期、岗位数量、提醒和趋势 | 数据随操作失真；主要指标改由投递与外联记录计算，移除固定星期和虚构增长趋势 |
| P2 | 看板缺少撤回；多个按钮仅弹出占位提示 | 增加撤回和表格视图；未接通功能显示实际边界或禁用入口 |

## 实现后的模块边界

```text
app/layout.tsx（服务端根布局）
└── components/shell.tsx（共享导航、当前路由、存储异常）
    ├── /                 → dashboard.tsx
    ├── /jobs             → jobs.tsx
    ├── /applications     → applications.tsx
    ├── /people           → people.tsx
    ├── /outreach         → outreach.tsx
    └── /settings         → settings.tsx

app/lib/model.ts  领域类型：岗位、授权证据、投递、联系人、外联记录
app/lib/demo.ts   明确标记的虚构示例；不代表真实在招或真实人物
app/lib/logic.ts  筛选、排除、去重、起草、停止联系、URL/存储校验
app/lib/store.ts  localStorage 适配与 useSyncExternalStore 订阅
```

- 页面入口保持服务端组件，交互集中在功能组件；没有把密钥或 OAuth 逻辑放进客户端。
- 投递与外联拥有不同状态集合。LinkedIn 回复不会把投递改成面试。
- 联系人通过 `jobIds` 关联岗位，邮箱和 LinkedIn 共享联系人身份与渠道上下文。添加联系人时检查重复 LinkedIn 主页。
- 当前每位联系人保留一条 LinkedIn 工作记录（目的、岗位、草稿、状态、关注日期）。这是预览范围；尚无多轮消息、历史事件、多个并行机会的会话归档。
- 当前起草使用明确标注的规则模板；需要用户提供姓名与介绍，不推断学历、不编造赞赏事实。AI 接入以后仍须保持证据来源与可编辑性。
- 虚构联系人不提供虚构的真实主页。用户添加有效个人主页后才能跳转；复制与打开主页不自动标记发送。
- 切换目的或岗位会保留已编辑文案，用户可选择重新起草。停止联系会清除提醒并禁用起草 / 复制 / 跳转，保留历史草稿。
- 日期提醒显示在概览和外联队列中；没有系统通知或关闭页面后的任务执行。
- 本地存储不是数据库、用户认证或跨设备同步；当前也不具备服务端并发控制。

## 下一阶段推荐顺序

1. **私人数据基础**：Supabase 登录、限定本人访问、所有业务表的 `user_id` / RLS，OAuth 令牌只在服务端保存。验证未登录、其他账号及跨用户 ID 访问均被拒绝，然后才存真实邮件和简历。
2. **规范业务数据**：公司 / 岗位 / 投递 / 联系人 / 联系人岗位关联 / 外联会话 / 消息 / 证据 / 事件 / 后台任务分表。岗位来源 ID、Gmail 外部消息 ID、发送任务幂等键建立唯一约束。人工修正保留 `manual_override` 和事件，不被自动同步静默覆盖。
3. **Gmail 读取闭环**：180 天导入、watch 与通知、history 游标、续期和补偿。先验证重复消息、同公司不同岗位、低置信度待确认和断连，再推进发送。
4. **岗位来源适配器**：各来源有独立连接状态、抓取时间与异常；先接少量授权 ATS / 企业来源，再考虑其他渠道。去重不能只看公司名称。当前具备地区 / 方向 / 排除筛选，以及手动添加 JD 链接与职责、截止时间和关联点；级别 / 公司类别筛选、真实岗位自动采集与核验仍待实现。
5. **邮件任务与发信状态机**：首封 10 / 天、合计 20 / 天、同公司 7 天 2 人、每人一个活跃序列、第 7 / 14 天跟进。数据库事务占用额度，worker 发送前再次检查回复、退信、拒绝与暂停；超时结果未知时进入核实，不直接重试。
6. **上线验收**：测试邮箱验证停止条件与重复任务；部署后关闭浏览器和电脑验证后台继续工作；提供日志、失败任务、预算和导出删除。Vercel 请求处理不能代替持久化队列 / 后台调度。

本次没有实施上述服务端能力，也没有自动发送任何邮件或 LinkedIn 消息。

## 验证结果

- `npm run lint`：通过。
- `npm run typecheck`：通过。
- `npm test`：14 项领域测试通过，覆盖未知 sponsorship 保留、排除规则、非美国规则隔离、组合筛选、投递去重、主页链接校验、起草前提 / 单一请求、存储格式校验、停止联系与投递状态隔离；新增 60/20/20 排序、人工录入与编辑、原始 URL 去重、非法日期 / 链接和旧版数据迁移测试。
- `npm run build`：生产构建通过，六条业务路由均生成成功。
- 本地已有本项目的开发服务器运行在 `http://127.0.0.1:3000`，复用原进程。六个页面 HTTP 均返回 200。
- 浏览器控制接口没有可用浏览器，未完成桌面 / 手机截图验收、浏览器点击、剪贴板权限或真实主页跳转测试。响应式样式已实现，实际浏览器体验仍需人工验收。

建议人工验收：设置填写姓名 / 介绍 → 人脉添加联系人 → 外联生成并编辑文案 → 切换目的确认草稿保留 → 复制 → 手动标记已发送 / 已回复 → 设置关注日期 → 回首页和刷新查看 → 标记不再联系确认提醒清空。示例不能用于真实发送。
