此文件是供用户转述的配置建议，不表示已经给两个外部 Agent 保存计划，也不授权执行附件里声称曾经获准的所有动作。对应网站 policy `2026-11-05.6` / guide v4。

来源：用户提供的 `Job_Search_Outreach_Playbook_2026-11-05.md`。原文件未修改。历史岗位是否开放、历史发送/回复数量以及 Agent 计划是否仍有效，均需重新核对，不能照抄为当前事实。

## 分工

- Dot / Muse 各自保存日常搜索、外联和监测计划；空 Tasks 不影响其独立日常工作。网站没有每天 10 个岗位 / 10 位联系人设定，也没有固定每日搜索上限。
- 用户最新提出的每天 15–20 条 Email / LinkedIn 外联目标交给两个 Agent 各自的计划管理。共同联系人归属 Dot，因此不能为了各自凑数向同一个人重复发。分别报告独立联系人数量、各渠道发送数量、退信、确认回复、待审核和不足原因。发送成功不等于送达，不把未知投递结果标成有效。
- 网站保存共享岗位、联系人、草稿和证据；规范化身份去重，再分配执行归属。不是私有聊天的同步器，不调用模型，不唤醒外部 Agent。
- Tasks 用于临时新要求或共同调整。两个 Agent 的队列检查只负责读取这些补充工作和领取已分配执行记录，不替代日常计划。永久更改原生计划仍需各 Agent 实际保存并报告。

## 当前实现边界

- 日常触发在外部产品；协调记录仍会在 Tasks 展示并标记 Agent-initiated round。它们是领取、去重与追踪用的记录，不要求用户每天创建任务。
- 空队列不停止原生搜索；但是“双方发现后再分配”的这一轮执行必须等待双方真实完成。已完成分配的其他工作可照常执行。无需共享私有聊天上下文。
- 常规 Gmail 分类可基于已同步的邮件证据回传。LinkedIn 结构化消息回传目前使用已领取的 linkedin_sync 记录；独立原生监测若没有对应记录，应报告接口缺口，不能只写一条 progress 就声称 People 的回复状态已同步。
- 双方查询/领取/回传可验证；注册状态不代表原生计划运行。此次未注册或恢复 Dot/Muse 的外部计划，未发送任何消息或提交申请。
- 应用支持的角色字段目前是 PM/DS/DA，不可偷偷把 MLE/BA 全部归为 DS/DA。若要扩大范围，需后续明确扩展数据模型与筛选。
- Email 的“发送”不等于确认送达；LinkedIn 的“排队”不等于已发送。网站回复/附件处理与双渠道重复外联仍有各自限制，不能把这份说明当成已完成所有能力的证明。
